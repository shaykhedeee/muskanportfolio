# Project Case Study Template

## Goal

A project page should prove design thinking and technical capability, not simply show a gallery.

## Project header

Required fields:
- project title
- slug
- category
- location
- year
- role
- scope
- software / tools
- hero image
- short project premise

Suggested facts row:
`Category / Scope / Location / Year / Role`

## Section 01 — Hero

Large image with restrained overlay text.

CTA options:
- `View Drawings`
- `View Visuals`

## Section 02 — Brief

Explain:
- client / user need
- space problem
- major constraints
- design objective

Keep under 140 words.

## Section 03 — Planning

Show:
- existing plan if permitted
- proposed plan
- furniture layout
- circulation or storage logic

Add 3–5 annotated callouts.

## Section 04 — Concept / Moodboard

Show:
- palette
- materials
- laminate / finish selection
- lighting direction
- key reference imagery

## Section 05 — 3D Development

Show 2–4 strong perspectives.

Optional interaction:
- working SketchUp model / clay render → photorealistic final reveal

## Section 06 — Furniture / Modular Detail

For relevant projects:
- kitchen
- wardrobe
- TV unit
- crockery
- pooja
- study
- vanity
- custom storage

Show 2D drawing + corresponding 3D result where possible.

## Section 07 — Design Decisions

Use three concise cards:
- Function
- Material
- Detail

Example format:

`FUNCTION — Moved storage to the full-height wall to preserve circulation around the bed.`

Do not publish private client information.

## Section 08 — Final Gallery

Editorial image grid with 4–8 visuals.

Use full bleed sparingly.

## Section 09 — Outcome

Short conclusion:
- what improved
- what was solved
- what Muskan was responsible for

Do not invent quantitative claims.

## Section 10 — Next Project

Large next-project preview with shared image transition.

## Project page scrolling

Project pages should feel smoother and less rigid than the homepage.

Recommended:
- normal vertical scroll
- selective sticky/pinned image sequences
- no forced one-section-per-wheel behavior
- optional snap only for major visual chapters
